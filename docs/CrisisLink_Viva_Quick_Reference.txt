SQL service -> real embedded PostgreSQL through PGlite: records and pgvector.

MongoDB $text is keyword search; vectors are in PostgreSQL, not MongoDB.
No separate Express backend. No external embedding API required.

VECTOR WORKFLOW
Location text -> exact alias + area-filtered cosine suggestions -> human confirms
  canonical saved location ID. Similar place does not prove same address.
Incident text -> vector -> same location, active status, last ONE HOUR -> review.
Human attaches incoming report as Mongo note or creates a separate SQL incident.
Lower cosine distance means closer vectors. 0.65 is a heuristic, not confidence.
Description edit invalidates old embedding; indexing regenerates current vectors.
One hour is a lookback, not a reporting deadline. Older incidents remain listed.
Yesterday's sample incidents naturally age out. Use fresh incidents for the viva.
SQL and MongoDB have no shared distributed atomic transaction.

  area_open: `
    SELECT l.area, COUNT(*) AS open_incidents
    FROM emergencies e
    JOIN locations l ON l.location_id=e.location_id
    WHERE e.status IN ('reported','responding')
    GROUP BY l.area
    ORDER BY open_incidents DESC, l.area
  `,

OTHER SELECT QUERIES TO PUT IN A labQueries TEMPLATE STRING

SELECT e.emergency_id,t.type_name,l.location_name,e.status
FROM emergencies e JOIN emergency_types t USING(type_id)
JOIN locations l USING(location_id) ORDER BY e.reported_at DESC;

SELECT r.resource_name,c.capability_name
FROM resources r JOIN resource_capabilities rc USING(resource_id)
JOIN capabilities c USING(capability_id) ORDER BY r.resource_name;

WITH ranked AS (
  SELECT emergency_id,status,changed_at,
    ROW_NUMBER() OVER(PARTITION BY emergency_id
      ORDER BY changed_at DESC,history_id DESC) AS rn
  FROM emergency_status_history
)
SELECT * FROM ranked WHERE rn=1;

SELECT e.emergency_id,e.description FROM emergencies e
WHERE NOT EXISTS(SELECT 1 FROM assignments a
  WHERE a.emergency_id=e.emergency_id AND a.status IN ('active','dispatched'));

SELECT * FROM v_assignment_summary ORDER BY assignment_id DESC;
SELECT * FROM emergency_status_history ORDER BY changed_at DESC,history_id DESC;

CUSTOM SQL IN A TERMINAL
PGlite is embedded: there is no psql TCP server. STOP APP FIRST before standalone
access to the same SQL folder. While app stays running, use its SQL-lab API.
Create scripts/custom-query.ts with this code:

import {getDb} from "../lib/db";
const db=await getDb();
try {
  const result=await db.query(`
    SELECT severity_level,COUNT(*) AS incident_count
    FROM emergencies GROUP BY severity_level
    ORDER BY incident_count DESC
  `);
  console.table(result.rows);
} finally { await db.close(); }

Run from project root: pnpm exec tsx scripts/custom-query.ts
Restart afterwards: pnpm start
Use SELECT for exploration. Direct owner queries are not an API-role test.
Schema/function edits may need a migration or CREATE OR REPLACE FUNCTION on an
already initialized database. Do not reset saved data to demonstrate changes.

// Latest notes

// Replace302 with an incident ID visible in your app
db.field_notes.find({emergency_id:302})

// Keyword text search; uses existing text index, not vectors
db.field_notes.find({$text:{$search:"smoke electrical"}})
db.field_notes.find({emergency_id:302,$text:{$search:"smoke"}})

// Array tag, substring search and recent notes
db.field_notes.find({tags:"additional-report"})
db.field_notes.find({text:{$regex:"smoke",$options:"i"}})
db.field_notes.find({created_at:{$gte:new Date(Date.now()-60*60*1000)}})

// Notes per incident
db.field_notes.aggregate([
  {$group:{_id:"$emergency_id",note_count:{$sum:1}}},
  {$sort:{note_count:-1}}
])

// Tag frequencies: unwind expands array elements into pipeline documents
db.field_notes.aggregate([
  {$unwind:"$tags"},
  {$group:{_id:"$tags",count:{$sum:1}}},
  {$sort:{count:-1}}
])

New SQL incidents do not automatically have Mongo notes. Empty results may be valid.
Create a field note or attach an additional report through the application first.
The SQL incident reference is checked by the backend, not a Mongo foreign key.
